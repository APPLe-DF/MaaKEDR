# 连接设置

MaaKEDR 通过 ADB 连接模拟器或 Android 设备。正确配置连接是任务执行的前提。

> [!NOTE]
>
> **使用安卓版 APK 的读者可以跳过本页。** 安卓版不走 ADB，而是由 Shizuku 或 root 直接取得截屏与点击权限，装好授权即可使用，无需配置连接。本页面向的是**桌面版 + 模拟器**的用法。

---

## 自动检测

大多数情况下，保持有且仅有目标模拟器启动，MaaKEDR 的 **连接** 板块会自动检测到它。点击 **刷新** 可重新扫描。

检测到模拟器后，**连接状态** 指示灯变为绿色即可开始使用。

若自动检测失败，可按以下顺序尝试：

1. 确认模拟器的 **ADB 调试** 已开启（各模拟器的开关位置见下文 [模拟器官方文档](#模拟器官方文档)）
2. 关闭其它模拟器实例，只保留目标实例
3. 以 **管理员权限** 运行 MaaKEDR，再点击 **刷新**
4. 仍然失败时，点击 **自定义** 手动填写，见下节

## 手动配置

完整的连接设置包含 **ADB 路径** 与 **ADB 地址** 两项；部分图形界面还会额外提供截图方式、输入方式（触控模式）等高级项，**一般保持默认即可**。

### ADB 路径

ADB 路径指向 MaaKEDR 连接模拟器所用的 `adb` 可执行文件。它一般由模拟器自带，也可以改用谷歌官方提供的 ADB。

#### 使用模拟器自带的 ADB

1. 启动模拟器，打开任务管理器，在模拟器进程上右键 → **打开文件所在的位置**
2. 在安装目录的顶层或下一层中，查找文件名中带有 `adb` 的 exe
3. 在 **ADB 路径** 中选中它

常见文件名示例：`adb.exe`、`HD-adb.exe`、`adb_server.exe`、`nox_adb.exe`。

#### 使用谷歌官方 ADB

前往 [platform-tools 下载页](https://dl.google.com/android/repository/platform-tools-latest-windows.zip) 下载并解压，然后选择其中的 `adb.exe`。

> [!TIP]
>
> 推荐直接解压到 MaaKEDR 文件夹下，这样 **ADB 路径** 可以填写相对路径 `.\platform-tools\adb.exe`，也能随 MaaKEDR 文件夹一起移动。

### ADB 地址

运行在本机的 ADB 地址形如 `127.0.0.1:<端口号>` 或 `emulator-<四位数字>`。

各模拟器默认 ADB 端口：

| 模拟器         | ADB 地址                                                                              | 备注                    |
| :------------- | :------------------------------------------------------------------------------------ | :---------------------- |
| MuMu 模拟器 12 | `127.0.0.1:16384`（多开：`16416`/`16448`/`16480`/`16512`/`16544`/`16576`）            | 需在设置中开启 ADB 调试 |
| BlueStacks 5   | `127.0.0.1:5555`（多开：`5554`/`5556`/`5565`/`5575`/`5585`/`5595`）                   | 需开启 ADB 调试         |
| LDPlayer 9     | `127.0.0.1:5555`（多开：`5557`/`5559`/`5561`）或 `emulator-5554`/`5556`/`5558`/`5560` | 默认已开启              |
| 夜神模拟器     | `127.0.0.1:62001`（多开：`59865`）                                                    | 默认已开启              |
| 逍遥模拟器     | `127.0.0.1:21503`                                                                     | 需开启 ADB 调试         |

> [!TIP]
>
> 上表中的多开端口仅为常见值，实际端口请以模拟器多开管理器中显示的为准。可在模拟器设置中查看 ADB 调试开关。MuMu 12 需在"设置中心 → 其他"中开启 ADB；BlueStacks 需在"设置 → 高级 → Android 调试桥"中开启。
>
> 表中的 `/` 表示**或者**，请按实际情况填写，不要照搬。

#### 模拟器官方文档

- [MuMu 模拟器 12](https://mumu.163.com/help/20230214/35047_1073151.html) `127.0.0.1:16384`
- [BlueStacks 5](https://support.bluestacks.com/hc/zh-tw/articles/360061342631) `127.0.0.1:5555`
- [雷电模拟器 9](https://help.ldmnq.com/docs/LD9adbserver) `emulator-5554`
- [夜神模拟器](https://support.yeshen.com/zh-CN/qt/ml) `127.0.0.1:62001`
- [逍遥模拟器](https://bbs.xyaz.cn/forum.php?mod=viewthread&tid=365537) `127.0.0.1:21503`

其他模拟器的 ADB 端口可参考 [赵青青的博客](https://www.cnblogs.com/zhaoqingqing/p/15238464.html)。

#### 获取多开端口

- **MuMu 12**：多开器右上角可查看正在运行的多开端口
- **BlueStacks 5**：模拟器设置内可查看当前的多开端口

如果界面上找不到，可以用 ADB 命令反查：

1. 只启动**一个**模拟器，并确保没有其它安卓设备连接在本机
2. 打开终端，进入存放 `adb` 可执行文件的目录，执行：

    ```shell
    # Windows 命令提示符
    adb devices
    # Windows PowerShell
    .\adb devices
    ```

3. 输出示例：

    ```text
    List of devices attached
    127.0.0.1:16384  device
    emulator-5554    device
    ```

4. 把输出中的 `127.0.0.1:<端口>` 或 `emulator-<四位数字>` 填入 **ADB 地址**

> [!TIP]
>
> 也可以打开 Windows **资源监视器** → **网络** 选项卡，在 **侦听端口** 中查找模拟器进程（如 `HD-Player.exe`）占用的端口，再在 **TCP 连接** 中查找 `adb.exe` 对应的远程端口，两者一致的那个即为调试端口。

### 触控模式

MaaFramework 会自动检测可用的截图方式与输入方式，**绝大多数情况下无需手动选择**。只有当连接成功、任务却"点不动"时才需要关注。

MaaFramework 的输入方式大致分三类：

1. **Minitouch**：用 C 编写的 Android 触控事件注入器，直接操作 `evdev` 设备，速度快。从 Android 10 开始，在 SELinux 为 `Enforcing` 模式时不再可用。
2. **MaaTouch**：MAA 基于 Java 对 Minitouch 的重新实现，使用安卓原生的 `InputDevice`，并增加了额外特性。高版本 Android 上的可用性请以实测为准。
3. **Adb Input**：直接调用 ADB 的 `input` 命令，兼容性最强、速度最慢。

如果当前方式点击无效（部分模拟器 ADB 版本较低时较常见），可在 **自定义** 中更换输入方式或更换一个 ADB 再试。

### 同时运行多个模拟器

MaaKEDR 的一个实例同一时间只操作一个模拟器。需要同时挂多台时，请参阅 [常见问题](./faq) 的「多开配置与批量启动」。

## 连接验证

在终端中执行以下命令可手动验证 ADB 连接：

```shell
adb devices
```

正常输出应显示已连接的设备列表，状态为 `device`：

```text
List of devices attached
127.0.0.1:16384  device
```

若状态为 `offline`、`unauthorized`，或列表为空，请回到上文检查 ADB 路径与地址。

## 多模拟器实例

如果启动了多个模拟器实例，MaaKEDR 会列出所有检测到的设备。请确保选择正确的目标实例。建议运行 MaaKEDR 时只启动一个模拟器实例以避免混淆。
